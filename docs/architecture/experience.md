# Опыт

Запись опыта принадлежит одному студенту и одной компании. Компания уже должна существовать: в запросе передаётся её `companyId`. Создать компанию на этом шаге нельзя.

Опыт не входит в карточку студента. Его создают, меняют и удаляют отдельными запросами `/experience`.

## Кто что может

Создавать, менять и удалять могут студент и админ.

Студент работает только со своей карточкой. Если в теле передан чужой `studentId`, сервер его игнорирует и берёт карточку текущего студента.

Админ обязан передать `studentId`. Без него создание отвечает **400**. Админ может создать и изменить опыт любого студента.

Рекрутер эти методы не вызывает.

Чтение доступно студенту, рекрутеру и админу.

- Свою карточку студент видит всегда.
- Админ видит любую.
- Чужую карточку видят одобренный студент и рекрутер, если у неё `catalogVisible=true` и аккаунт владельца `APPROVED`.
- Иначе **404**, не **403**. Студент без одобрения чужие записи не видит.

## Поля

| Поле | В запросе | Смысл |
|---|---|---|
| `companyId` | обязательно | Id компании |
| `studentId` | админу обязательно, студенту нет | Чья запись |
| `position` | обязательно | Должность или роль, 1–255 символов |
| `additionalInfo` | нет | Описание, до 2000 символов |
| `startDate` | обязательно | Дата начала, `yyyy-MM-dd` |
| `endDate` | нет | Дата окончания. Пустое значение значит, что опыт ещё идёт |
| `experienceType` | нет | `WORK` или `PROJECT` |

`WORK` — опыт работы. `PROJECT` — проектная деятельность. Подписи показывает фронт, в API уходят коды.

Если при создании тип не передан, сохраняется `WORK`. Если при обновлении тип не передан, уже записанный тип не меняется. Неизвестный код — ошибка запроса.

`endDate` не может быть раньше `startDate`. Один и тот же день допустим. Пустая `endDate` значит, что опыт ещё идёт. Иначе ответ **400**.

Старые записи в базе тоже имеют тип `WORK`.

## Ответ

Создание, обновление, чтение одной записи и элемент списка устроены одинаково.

```json
{
  "companyId": 1,
  "companyWebsite": "https://company.example",
  "studentId": "aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa",
  "experience": {
    "id": 10,
    "position": "Разработчик",
    "additionalInfo": null,
    "startDate": "2020-01-01",
    "endDate": null,
    "experienceType": "WORK"
  }
}
```

`companyWebsite` — ссылка компании. Если у компании её нет, поле `null`.

`experienceType` в ответе есть всегда. Пустым он не бывает.

## Методы

`GET /experience/{id}` — одна запись. **200** или **404**.

`POST /experience/filter` — страница записей. Тело: `studentId` и `companyId`, оба необязательны.

- Студент без `studentId` получает только свой опыт.
- Переданный чужой `studentId` не подменяется. Доступ проверяется по правилам чтения выше.
- Фильтр по `companyId` доступен только админу. Остальным — **403**.
- Пагинация: `page` и `size` в query. Параметр `sort` не используется.

Ответ — страница: `data`, `page`, `size`, `totalElements`, `totalPages`.

`POST /experience` — создать. **201** и запись. Компании с таким `companyId` нет — ошибка.

`PUT /experience/{id}` — заменить поля записи. Студент меняет только свою. Те же поля, что при создании.

`DELETE /experience/{id}` — удалить. **204**. Студент удаляет только свою. Запись не найдена — **404**.

## Что происходит с анкетой

Если студент сам создаёт, меняет или удаляет опыт, статус его аккаунта меняется так:

- был `APPROVED` или `REJECTED` — становится `PENDING_APPROVAL`;
- карточка скрывается: `catalogVisible=false`;
- причина и комментарий отказа очищаются;
- был уже `PENDING_APPROVAL` — статус не трогается.

Правка админом статус студента не меняет.

Подробнее про статусы: [account-review.md](./account-review.md).
