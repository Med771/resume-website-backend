# Анкета студента

Карточка студента — одна запись на аккаунт. Опыт, учёба и портфолио к ней не входят: их меняют отдельные запросы. Проверка и показ карточки описаны в [account-review.md](./account-review.md). Опыт — в [experience.md](./experience.md).

Учёба студента — `POST /institution`. Тип `educationType`: `STATE` — гос. образование, `COURSE` — образовательные курсы. Если при создании тип не передан, сохраняется `STATE`. Если при обновлении тип не передан, уже записанный тип не меняется. В ответе тип есть всегда. Справочник учебных заведений `/education` тип не хранит.

Саморегистрация `POST /auth/register-student` сразу создаёт пользователя и черновик. Статус `PENDING_APPROVAL`, `catalogVisible` выключен. На почту уходит код из 4 цифр. В форме: логин, пароль, почта, телефон, дата рождения с 14 лет. Имя, фамилия, отчество и город можно не передавать.

Админ создаёт готовую карточку вместе с учётной записью: `POST /student`.

## Кто что может

Читать полную карточку могут студент, рекрутер и админ.

- Свою карточку студент видит всегда: `GET /student/me`.
- Админ видит любую: `GET /student/{id}`.
- Чужую карточку видят одобренный студент и рекрутер, если `catalogVisible=true` и аккаунт владельца `APPROVED`.
- Иначе **404**, не **403**.

Короткие списки: `POST /student/cardsFilter`. Полные: `POST /student/filter`. Пагинация — `page` и `size`. Порядок задают `sortBy`, `sortDirection` и `useDefaultRanking` в теле. Query-параметр `sort` игнорируется.

`GET /public/students/{id}` и `POST /public/students/cards` требуют вход. Это укороченная карточка без контактов.

Менять свою карточку может студент: `PATCH /student/me` и фото `POST /student/photo/{id}`. Чужую — нет.

Админ создаёт, полностью заменяет (`PUT /student/{id}`), частично меняет (`PATCH /student/{id}`), ставит фото и удаляет карточку. Ручной порядок и массовый показ — `POST /admin/students/reorder` и `POST /admin/students/bulk-visibility`.

Правка своей карточки, фото, опыта, учёбы или портфолио возвращает `APPROVED` и `REJECTED` на проверку и скрывает карточку. Правка админом статус не меняет.

## Поля карточки

| Поле | В запросе | Смысл |
|---|---|---|
| `firstName`, `lastName` | при создании админом обязательны | Имя и фамилия |
| `middleName` | нет | Отчество |
| `gender` | нет | `MALE` или `FEMALE`. Пусто — не указан |
| `birthDate` | при создании админом обязательна | Дата рождения, не раньше 14 лет |
| `city` | нет | Город |
| `email`, `phoneNumber`, `telegramUsername` | нет | Контакты. `telegramUsername` — строка в анкете |
| `hhLink` | нет | Ссылка на HeadHunter |
| `bio` | нет | Текст до 2000 символов |
| `course` | при создании админом обязателен | `FIRST` … `FIFTH`, в базе `1` … `5` |
| `busyness` | при создании админом обязательна | Тип занятости |
| `desiredBusyness` | нет | Желаемая занятость. На макете «Желаемый формат». Пусто — не указана |
| `jobSearchStatus` | нет | Статус поиска работы. Пусто — не указан |
| `specialityId` | при создании админом обязателен | Специальность из справочника |
| `skillsIds` | при создании админом обязателен | Навыки по id |

В ответе специальность приходит именем `speciality` и id `specialityId`. Навыки — списком `{ id, name }`.

`busyness` в JSON — имя константы, в базе — короткая строка.

| Код | В базе | Смысл |
|---|---|---|
| `EMPLOYED` | `employed` | Фулл-тайм |
| `FREELANCE` | `freelance` | Парт-тайм |
| `FREE` | `free` | Нет занятости |
| `PROJECT_WORK` | `project_work` | Проектная работа |

`PROJECT_WORK` — занятость студента. Это не тип строки опыта `ExperienceType.PROJECT` и не тип вакансии `VacancyEmploymentTypeEnum.PROJECT`.

`desiredBusyness` использует те же коды. На макете поле называется «Желаемый формат» и предлагает `EMPLOYED`, `FREELANCE` и `PROJECT_WORK`. Если его не передать, в базе `null`. В `PATCH` и `PUT` пустое поле уже записанное значение не затирает. Одобрение анкеты его не требует.

`jobSearchStatus`:

| Код | В базе | Смысл |
|---|---|---|
| `LOOKING` | `looking` | Ищу работу |
| `CONSIDERING` | `considering` | Рассматриваю предложения |
| `NOT_LOOKING` | `not_looking` | Не ищу работу |

Если статус поиска не передан при создании, в базе `null`. В `PATCH` пустое поле уже записанный статус не затирает. То же правило у остальных необязательных полей частичного обновления: `null` значит «не менять». `PUT` тоже не затирает статус поиска, если поле не передано.

Фото в теле карточки нет. Его ставит `POST /student/photo/{id}`, файл в `multipart`. В ответе остаётся `imagePath`.

## Служебные поля ответа

Их не заполняет студент как текст анкеты.

- `catalogVisible` — показ в каталоге. Правила в [account-review.md](./account-review.md).
- `publicProfileConsent` устарел. Каталог `/public/students` всё ещё читает его вместе с `catalogVisible`.
- `profileTextScore` считает сервер при сохранении карточки. Поле участвует в сортировке.
- `manualSortOrder` задаёт только админ. Меньше число — выше в каталоге. `null` — номер не задан. Сброс: `clearManualSortOrder: true`.

## Что нужно для одобрения

Админ не одобрит студента, пока не собраны фото, портфолио, опыт, учёба, описание от 30 символов, имя, фамилия, специальность, курс, не меньше 5 навыков, занятость и город. Статус поиска работы в этот список не входит. В ответе **400** перечислены все пробелы сразу. Почта к этому моменту уже подтверждена.
