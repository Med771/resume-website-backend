# Учёба

Учёба студента — отдельная запись. Учебное заведение уже должно существовать: в запросе передаётся его `educationId`. Создать заведение на этом шаге нельзя.

Учёба не входит в карточку студента. Её создают, меняют и удаляют запросами `/institution`. Справочник заведений — `/education`.

## Кто что может

Создавать, менять и удалять запись учёбы могут студент и админ.

Студент работает только со своей карточкой. Если в теле передан чужой `studentId`, сервер его игнорирует и берёт карточку текущего студента.

Админ обязан передать `studentId`. Без него создание отвечает **400**. Админ может создать и изменить учёбу любого студента.

Рекрутер эти методы не вызывает.

Чтение доступно студенту, рекрутеру и админу.

- Свою карточку студент видит всегда.
- Админ видит любую.
- Чужую карточку видят одобренный студент и рекрутер, если у неё `catalogVisible=true` и аккаунт владельца `APPROVED`.
- Иначе **404**, не **403**. Студент без одобрения чужие записи не видит.

Справочник `/education` читают все три роли. Создавать и менять заведение могут студент и админ. Удалять заведение может только админ.

## Поля записи учёбы

| Поле | В запросе | Смысл |
|---|---|---|
| `educationId` | обязательно | Id учебного заведения |
| `studentId` | админу обязательно, студенту нет | Чья запись |
| `startYear` | обязательно | Год начала, 1900–2100 |
| `endYear` | обязательно | Год окончания, 1900–2100 |
| `educationType` | нет | `STATE` или `COURSE` |
| `direction` | нет | Направление, до 255 символов |
| `educationLevel` | нет | Уровень образования, до 255 символов |

`STATE` — гос. образование. `COURSE` — образовательные курсы. Подписи показывает фронт, в API уходят коды.

Если при создании тип не передан, сохраняется `STATE`. Если при обновлении тип, направление или уровень не переданы, уже записанные значения не меняются. Неизвестный тип — ошибка запроса.

Старые записи в базе тоже имеют тип `STATE`. Направление и уровень у них пустые.

## Ответ

Создание, обновление, чтение одной записи и элемент списка устроены одинаково.

```json
{
  "educationId": 1,
  "studentId": "aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa",
  "institution": {
    "id": 10,
    "startYear": 2020,
    "endYear": 2024,
    "educationType": "STATE",
    "direction": "Информатика",
    "educationLevel": "Бакалавриат"
  }
}
```

`educationType` в ответе есть всегда. Пустым он не бывает. `direction` и `educationLevel` могут быть `null`.

## Методы учёбы

`GET /institution/{id}` — одна запись. **200** или **404**.

`POST /institution/filter` — страница записей. Тело: `studentId` и `educationId`, оба необязательны.

- Студент без `studentId` получает только свою учёбу.
- Переданный чужой `studentId` не подменяется. Доступ проверяется по правилам чтения выше.
- Фильтр по `educationId` доступен только админу. Остальным — **403**.
- Пагинация: `page` и `size` в query. Параметр `sort` не используется.

Ответ — страница: `data`, `page`, `size`, `totalElements`, `totalPages`.

`POST /institution` — создать. **201** и запись. Заведения с таким `educationId` нет — ошибка.

`PUT /institution/{id}` — заменить поля записи. Студент меняет только свою. Те же поля, что при создании.

`DELETE /institution/{id}` — удалить. **204**. Студент удаляет только свою. Запись не найдена — **404**.

## Справочник заведений

Запись справочника — название, описание и сайт. Типа, направления и уровня у неё нет.

| Поле | В запросе | Смысл |
|---|---|---|
| `institution` | обязательно | Название, 1–255 символов |
| `additionalInfo` | обязательно | Описание, 1–2000 символов |
| `webUrl` | обязательно | Сайт, 1–255 символов |

`GET /education/{id}` — одна запись.

`POST /education/filter` — страница. Тело: `ids`, `institution`, `additionalInfo`, `webUrl`, все необязательны. Пагинация `page` и `size`. Параметр `sort` не используется.

`POST /education` — создать. **201**. Студент и админ.

`PUT /education/{id}` — заменить поля. Студент и админ.

`DELETE /education/{id}` — удалить. Только админ. **204**.

## Что происходит с анкетой

Если студент сам создаёт, меняет или удаляет свою учёбу, статус его аккаунта меняется так:

- был `APPROVED` или `REJECTED` — становится `PENDING_APPROVAL`;
- карточка скрывается: `catalogVisible=false`;
- причина и комментарий отказа очищаются;
- был уже `PENDING_APPROVAL` — статус не трогается.

Правка админом статус студента не меняет. Правка справочника `/education` статус анкеты не меняет.

Подробнее про статусы: [account-review.md](./account-review.md).
