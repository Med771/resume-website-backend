# Компания

Компания — справочник организаций, к которым привязан опыт. Создать опыт без уже существующей компании нельзя: в запросе опыта передаётся её `id`.

У компании есть название и необязательная ссылка на сайт.

## Кто что может

Читать компанию могут студент, рекрутер и админ: одну запись и список.

Создавать и обновлять могут студент и админ.

Удалять может только админ. Если на компанию ещё ссылается опыт, удаление не проходит: **400**.

## Поля

| Поле | В запросе | Смысл |
|---|---|---|
| `name` | обязательно | Название, 1–255 символов |
| `website` | нет | Ссылка на организацию, до 255 символов |

`website` можно не передавать. Тогда при создании ссылки нет. При обновлении непереданное поле уже сохранённую ссылку не стирает. Пустая строка ссылку очищает.

В ответе поле есть всегда. Нет ссылки — `null`.

## Ответ

Чтение, список, создание и обновление отдают одно и то же.

```json
{
  "id": 1,
  "name": "Acme",
  "website": "https://company.example",
  "experiencesIds": [10, 11]
}
```

`experiencesIds` — id записей опыта, которые ссылаются на эту компанию. У только что созданной компании список пустой.

## Методы

`GET /company/{id}` — одна компания. **200** или **404**.

`POST /company/filter` — страница. В теле необязательная подстрока `name`, поиск без учёта регистра. Пагинация: `page` и `size` в query. Параметр `sort` не используется.

Ответ — страница: `data`, `page`, `size`, `totalElements`, `totalPages`.

`POST /company` — создать. **201** и компания.

`PUT /company/{id}` — обновить название и, если передано, ссылку.

`DELETE /company/{id}` — удалить. **204**. Только админ.

## Связь с опытом

В ответе опыта ссылка компании называется `companyWebsite`. Это то же значение, что `website` у компании. Если ссылки нет, там `null`.

Тип записи опыта в её ответе всегда заполнен: `WORK` или `PROJECT`. Если при создании опыта тип не передали, сохраняется `WORK`.
