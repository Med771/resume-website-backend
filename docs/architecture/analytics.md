# Журнал посещений и действий

Все события лежат в одной таблице `analytics_events`. Админ смотрит их в `POST /admin/analytics/events`. Сводка по страницам — `POST /admin/analytics/summary`, сводка по типам — `POST /admin/analytics/funnel`. Время в запросе: с `from` включительно и до `to`, не включая конец.

## Что сервер пишет сам

Подключать ничего не нужно. Строка появляется в момент действия.

Письмо. Тип `EMAIL_SENT`. Сервер запоминает вид письма, адрес, тему и ушло оно или нет. Код и текст письма не хранятся. Если отправка сорвалась, в строке `success: false` и короткая ошибка.

Виды писем: код студенту, код смены пароля, регистрация завершена, анкета отправлена, аккаунт одобрен, аккаунт не одобрен, рассылка администратора.

Одобрение. Тип `ACCOUNT_APPROVED`. Кто нажал, кого одобрили, студент это или работодатель.

Отказ. Тип `ACCOUNT_REJECTED`. То же самое плюс причина и комментарий. Если причину не передали, эти два поля пустые.

Правка своей анкеты. Тип `STUDENT_PROFILE_CHANGED`. Только когда правит сам студент. Правка администратора в журнал не попадает. Пишется раздел и имена полей, без старого и нового текста.

Разделы: карточка, фото, опыт, учёба, портфолио. Для опыта, учёбы и портфолио ещё видно, строку создали, изменили или удалили.

Пример правки карточки:

```json
{
  "studentId": "bbbbbbbb-bbbb-bbbb-bbbb-bbbbbbbbbbbb",
  "section": "card",
  "action": "update",
  "fields": ["bio", "city"]
}
```

Пример письма:

```json
{
  "kind": "STUDENT_EMAIL_OTP",
  "to": "student@example.com",
  "subject": "Код подтверждения — Singularity Resume",
  "success": true
}
```

## Что надо подключить на сайте

Сервер не видит, какую страницу открыл человек. Пока сайт сам не отправит событие, посещений в журнале не будет.

Отправка: `POST /public/analytics/events`, без входа. В теле тип, путь страницы и, если есть, id сессии. Если человек уже вошёл, сервер сам допишет его id. Подробности в это событие класть нельзя: для посещений поле `payload` пустое.

Типы, которые сайт может прислать:

- `PAGE_VIEW` — открыл страницу
- `REGISTRATION_STARTED` — начал регистрацию
- `REGISTRATION_COMPLETED` — закончил регистрацию на экране
- `APPLICATION_SUBMITTED` — отправил отклик
- `REQUEST_SUBMITTED` — отправил заявку
- `CHAT_MESSAGE_SENT` — написал в чат
- `CHAT_TU_CONFIRMED` — согласился на тестовое
- `CHAT_TU_REJECTED` — отказался от тестового
- `CHAT_SUCCESS` — чат дошёл до успеха

`ACCOUNT_APPROVED` сайт тоже может прислать, если показывает экран после одобрения. Настоящее одобрение сервер уже пишет сам, с подробностями. Письмо «аккаунт одобрен» — это отдельная строка про почту, не второе одобрение.

Пример посещения:

```json
{
  "eventType": "PAGE_VIEW",
  "path": "/students",
  "sessionId": "6f1c0c3e-8c2a-4b1e-9d4a-1b2c3d4e5f60"
}
```

Письма, отказы и правки анкеты с сайта отправлять не нужно. Такой запрос сервер не примет.
