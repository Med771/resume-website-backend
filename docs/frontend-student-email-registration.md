# Саморегистрация студента: что менять на фронте

Студент больше не регистрируется через Telegram. Сначала создаём аккаунт и сразу логиним, потом подтверждаем **почту 6-значным кодом**. Рекрутерский Telegram не трогали.

Выкатывать бэкенд и новую форму **вместе**: старый фронт без `email` получит **400**.

Полный справочник API: [api-endpoints.md](./api-endpoints.md). Сценарии ролей: [roles-product-journeys.md](./roles-product-journeys.md). Cookie и CORS: [frontend.md](./frontend.md).

---

## 1. Новый сценарий

1. Форма → `POST /auth/register-student` (`credentials: 'include'`).
2. Ответ **204**, сразу cookie `ACCESS_TOKEN` / `REFRESH_TOKEN`. Пользователь уже в ЛК.
3. На email уходит **6 цифр** (не 4, как у телефона рекрутера).
4. Экран «введите код» → `POST /auth/confirm-email`.
5. Если письмо не пришло — кнопка «отправить ещё раз» → `POST /auth/resend-email-confirmation`.
6. Анкету (курс, пол, опыт и т.д.) заполняют **после** регистрации: `PATCH /student/me` и CRUD опыта / учёбы / портфолио.
7. Админ одобрит аккаунт только когда почта подтверждена. До этого студент в ЛК есть, в каталоге рекрутеров — нет.

Лишние поля старой формы (`phoneVerificationId`, `birthDate`, `course`) бэкенд просто проигнорирует.

---

## 2. `POST /auth/register-student`

**204**, cookie как после логина.

| Поле | Обязательно | Что это |
|------|-------------|---------|
| `username` | да | 3–64, латиница / цифры / `_` |
| `password` | да | политика как раньше (длина, буква + цифра) |
| `passwordConfirm` | да | должно совпасть |
| `email` | **да** | сюда уйдёт код |
| `phoneNumber` | да | просто контакт, **без бота**. Формат `+` и 7–15 цифр |
| `firstName` | нет | имя |
| `lastName` | нет | **фамилия** (как было в проде, ничего не переименовывали) |
| `middleName` | нет | **отчество**, новое поле. Не писать в `lastName` |
| `city` | нет | город |

Убрать с формы: Telegram-шаг, `phoneVerificationId`, дату рождения и курс на регистрации.

Ошибки:

- **400** — пароли, логин занят / зарезервирован, почта уже есть, слабый пароль;
- **429** — слишком много регистраций с IP.

Если письмо не ушло — аккаунт всё равно создан. Показать «код не пришёл? отправить снова».

## 3. Подтверждение почты

Нужна **уже установленная cookie** и роль `STUDENT`. Без сессии — **401**. Рекрутер — **403**.

### `POST /auth/confirm-email`

Тело:

```json
{ "code": "123456" }
```

Ровно **6 цифр**. Ответ **204**. Если уже подтверждена — тоже **204**.

### `POST /auth/resend-email-confirmation`

Без тела. **204**. Если почта уже подтверждена — **400** «уже подтверждена».

Код живёт около **15 минут**. Неверный / просроченный — **400**. Слишком много попыток / resend — **429** (примерно 8 попыток и 5 resend в час на пользователя).

Код не класть в URL и не логировать на клиенте.

## 4. `GET /auth/me`

Новое поле:

- `emailVerified` — `true` / `false`

Как раньше: `id`, `username`, `role`, `accountStatus` (`PENDING_APPROVAL` / `APPROVED` / `REJECTED`), `hintsDisabled`.

Это **два разных флага**:

- `emailVerified` — ввёл код с почты;
- `accountStatus` — админ одобрил.

После регистрации: cookie есть, `emailVerified: false`, `accountStatus: PENDING_APPROVAL`.  
После кода: `emailVerified: true`, статус всё ещё `PENDING_APPROVAL`, пока админ не апрувнет.

Экран «подтвердите почту», пока `role === 'STUDENT'` и `emailVerified === false`.

---

## 5. Анкета после регистрации

Новые поля в карточке и в `PATCH /student/me` (и в админских create / update / patch):

- `middleName` — отчество (есть и в короткой карточке `StudentCardDTO`);
- `gender` — `"MALE"` | `"FEMALE"` | `null` (не указан). **Только полная карточка и PATCH**, в каталожных карточках пола нет. Фильтра «по полу» нет.

Курс теперь **1–5**: к `FIRST`…`FOURTH` добавили `FIFTH`. В селекте курса — пять пунктов.

`null` в PATCH = «не менять». Пол на регистрации не передаём.

Фото студента по-прежнему админское `POST /student/photo/{id}`. Отдельного `/student/me/photo` нет.

## 6. Админка (если есть UI очереди)

`GET /admin/account-approvals` — в пользователе есть `emailVerified`.

`POST /admin/account-approvals/{userId}/approve` для студента без почты → **400** «ещё не подтвердил почту». Не апрувить, пока `emailVerified !== true`.

Рекрутерский approve как был.

---

## 7. Что не менялось

- Регистрация работодателя и `/verification/phone` (4-значный код / Telegram).
- Логин, refresh, logout, cookie.
- Имена JSON: `firstName` / `lastName` как раньше.

## 8. Чеклист фронта

- [ ] Форма студента: логин, пароль ×2, email, телефон; опционально ФИО + город. Без бота.
- [ ] После 204 — шаг с **6** цифрами кода + resend.
- [ ] По `GET /auth/me` баннер «подтвердите почту».
- [ ] В ЛК: отчество, пол, курс до 5-го.
- [ ] Старую форму без email не оставлять на этом API.
- [ ] Выкатка бэка и формы — вместе.
